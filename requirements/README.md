# 需求文档目录

本目录用于存放 plaita 项目的需求文档。AI 开发助手会根据这些文档中的需求逐一进行实现。

## 目录结构

```
requirements/
├── README.md                     # 本文件 - 目录说明
├── AI_DEVELOPMENT_GUIDE.md       # AI 开发提示指南
├── checkpoint-requirements.md    # Checkpoint 功能需求
└── [其他需求文档].md
```

## 需求文档规范

### 文件命名

- 使用小写字母和连字符
- 格式：`[模块名]-requirements.md` 或 `[功能名]-spec.md`
- 示例：`event-system-requirements.md`, `http-node-spec.md`

### 文档结构

每个需求文档应包含以下部分：

```markdown
# [功能名称] 需求文档

## 1. 概述
简要描述该功能的目的和背景。

## 2. 需求列表
### 2.1 [需求项名称]
- **状态**: [ ] 未开始 / [x] 已完成 / [~] 进行中
- **优先级**: 高/中/低
- **描述**: 详细描述需求
- **验收标准**: 如何验证需求已完成
- **相关文件**: 涉及的代码文件

## 3. 技术设计
（可选）技术实现方案

## 4. 依赖项
列出依赖的其他需求或外部依赖

## 5. 测试要求
测试覆盖要求

## 6. 更新记录
| 日期 | 更新内容 | 更新人 |
|------|----------|--------|
```

### 需求状态

使用以下标记表示需求状态：

- `[ ]` - 未开始
- `[~]` - 进行中
- `[x]` - 已完成
- `[-]` - 已取消

### 优先级

- **P0** - 紧急：必须立即处理
- **P1** - 高：当前迭代必须完成
- **P2** - 中：计划中的功能
- **P3** - 低：可以延后的功能

## 如何使用

1. **创建新需求**：在本目录下创建新的 `.md` 文件
2. **更新状态**：完成需求后更新状态标记
3. **AI 开发**：AI 助手会读取这些文档并逐一实现未完成的需求
