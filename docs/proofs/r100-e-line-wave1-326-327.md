## 单① #326：新 start 状态闸三格（`tenant_status.tenant_start_allowed` + `flow_worker` 接线）

**修法**：`_dispatch_task` 对 `type=="start"` 换三格闸（resume/决议载体维持
`tenant_is_active` fail-open 在飞豁免），返回 `(allowed, reason)` 与
`tenant_write_allowed` 同形状、复用 #312 `is_epistemic_reject_reason` 词汇表：

1. **格 1（认识论性）**：状态/世代 hget 读失败 → `(False,
   status_read_failed | generation_read_failed)`；新异常
   `TenantGateEpistemicReject` 由消费循环专门分支**载体不动**（不 ack、不
   重投、不收容——与 `TenantQuotaDeferred` 的重投语义刻意区分，A125-02 的
   教训是不给确认态留终局出口、#312 的教训是不给读失败造终局出口，两者
   方向相反不可共用一条通道）。重投烧 deliveries 触死信守卫时，守卫对读
   失败型原因不收容（#312 修后语义），闭环无终局化出口。
2. **格 2（确认态）**：`tenant_disabled` 照既有丢弃语义（#27 守恒）。
3. **格 3（记录缺失切刀，A133-03/A2R58-05 残留形态）**：status 缺 + 世代缺
   = 机制前租户 #237 fail-open 守恒；**status 缺 + 世代在** = 快照回滚/
   补偿残留（kill switch 被击败的状态）→ 具名
   `status_missing_generation_present` + WARNING + 进程内计数
   （`tenant_status_missing_generation_total()`）。
4. default/空租户、无 Redis 客户端：fail-open 守恒（#237/#27 兼容面不扩）；
   `expected_epoch` 非 legacy 时纪元闸（A2R31-02）经 `tenant_is_active` 收口，
   拒绝具名 `tenant_epoch_stale`。

## 单② #327：per-tenant DLQ 配额（新模块 `tenant_dlq_quota` + `task_queue` 三处 + console purge 配对）

**修法**：

- **计数键**：平台机制键 HASH `plaita:tenant_dlq_count`（tenant_id → 收容数），
  平台 DLQ 与租户隔离流**共用**（隔离流 console 不可见，只管 `*:dlq` 它就是
  绕行暗面）；写路径 HINCRBY 计数（A2 评审分工：闸门用写路径计数，观测扫描
  对账留给 #316 骨架复用的后续单）；全局 xtrim 挤旧时计数只朝虚高漂（保守
  方向），docstring 明示待扫描纠偏。
- **闸序**：`dead_letter()` 内 purity（#277 写闸）→ quota → XADD 单一写入口；
  满格抛 `TenantDlqQuotaFull`（具名 `dlq_quota_full`），由
  `dead_letter_if_allowed` 接住**留 pending**（满格=「无着陆点」，#312 同构；
  **不挤旧**）——配额满格不产生第二条流（A2 破面警告）。
- **隔离流同闸**：`_quarantine_rejected_dead_letter` 在收容 XADD 前同闸；
  确认态×满格留 pending 走独立计数 `dlq_quota_full_pending`，与认识论性
  `tenant_reject_epistemic_pending` 绝不混数（reason 可辨）。
- **两键成对**：console `delete_tenant` 清理步骤在 `dlq` 后新增
  `dlq_quota_count` 步（`_clear_tenant_dlq_quota` → `clear_tenant_dlq_count`）
  ——同 slug 重建不继承幻影计数；隔离流条目按 A125 证据保全刻意保留，但其
  计数随世代退役。
- **过半程告警**：HINCRBY 跨 `cap/2` 恰值时 WARNING 一次（事件名
  `tenant_dlq.quota_half`，带落点分流名 `platform_dlq`/`quarantine`）。
- **env**：`PLAITA_TENANT_DLQ_MAX_ENTRIES` 缺省 200（=平台 maxlen 1000 的
  20% 份额占位）；`0`=不限（关闭）；非法/负 loud 回默认。ops-runbook 已录
  （含与 `PLAITA_TENANT_QUOTA_DEFER_MAX` 同类的「读时 WARNING+回退」语义——
  不进 runtime_config 启动预检聚合，构造期解析一次）。
- 无显式 `tenant_id` 的载体：不可归属即不可闸，不参与配额（与 purge 同口径）。
