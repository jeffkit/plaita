# plaita#191 负控：还原「发布端绑定受信租户 + EventFilter 只认受信 tenant_id」

负控手法：把修法涉及的发布/消费两侧同时还原到 origin/main（原始漏洞形态）：

```bash
git checkout origin/main -- \
  plaita/event/core.py plaita/event/redis.py plaita/event/memory.py \
  plaita/event/sqlalchemy.py plaita/server/event_filter.py \
  plaita/server/services/base_service.py \
  plaita-console/backend/api/events.py
```

## repro（`docs/proofs/data/191-repro.py`，期望红）

```
"trusted_tenant": null,
"data_tenant": "globex",
"spoof_enqueued": 1,
"spoof_task_tenants": ["globex"],
"legit_enqueued": 0,
"publish_safe": false,
"consume_safe": false,
"verdict": "VULNERABLE（跨租户发布/注入链仍通）"
```

精确红点：租户 acme 的 editor 发布时在 `data.tenant_id` 自报 globex，事件
落库**没有**受信顶层租户（`trusted_tenant: null`）；EventFilter 用自报租户
加载到 globex 的挂起执行并**入队 1 条 resume**（`spoof_enqueued: 1`，
任务租户 `globex`）——即跨租户审批放行。
